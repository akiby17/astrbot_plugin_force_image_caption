# Force Image Caption 强制图片转述

**当前版本：v1.2.6**

为 **DeepSeek 等纯文本主模型** 自动补充图片理解。

## 它解决什么问题

普通用法仍然支持：

```text
[图片] @机器人 那这张呢
```

v1.2.0 进一步支持“先发图、下一条再问”的连续对话：

```text
用户：[图片]
用户：第二个是谁？
```

插件会自动完成：

```text
当前图片 / 最近图片
        ↓
视觉模型结合当前问题理解图片
        ↓
<image_caption> 视觉事实 </image_caption>
        ↓
纯文本主聊天模型自然回复
```

## 特点

- 自动处理当前图片、引用图片和多图
- **支持最近图片记忆**：单独发图后，下一条“第二个是谁 / 左边是谁 / 这张呢”等追问仍可识别
- **问题感知识图**：把当前用户问题作为视觉模型语境，不再只做泛化图片描述
- 最近图片默认仅保留 5 分钟，并通过追问判断降低误用旧图的概率
- 仅缓存图片引用，不复制图片二进制；插件重载/重启后缓存自动清空
- **自然续聊优先复用上一轮转述**，避免同一张图每句话都重复调用视觉模型
- **群聊当前轮聚焦**：图片触发 LLM 时保留历史语境，但不让模型顺手补回复前面未触发的群消息
- 相同图片 + 相同问题支持短时转述缓存，并对并发中的相同识图任务自动去重
- 默认串行发送视觉请求，降低瞬时 RPM 峰值
- 检测到 429/RPM/TPM/计费暂停后自动冷却，避免持续撞限额
- 视觉模型临时失败时仍支持可配置的插件级重试（AstrBot 4.28+ 默认建议 0）
- 多图整体失败后仍可逐张恢复，但只对适合拆分的批量/格式错误触发
- 空响应仍可按配置重试
- 全部重试失败后可静默降级，清理 `[Image Captioning Failed]` 等内部失败标记
- 可禁止主模型向用户回复“没看到图片 / 识图失败”，且不编造视觉内容
- AstrBot 已成功生成图片转述时直接复用，避免重复调用

## 最近图片追问

默认开启 `记住本会话最近图片` 和 `仅在疑似图片追问时复用最近图片`。

插件会优先识别这类追问：

```text
第二个是谁？
左边那个是谁？
这张呢？
图里写了什么？
这个表情包什么意思？
```

为了避免旧图干扰正常聊天，像“今天天气怎么样”这样的普通问题默认不会自动带上最近图片。

如需手动清除本会话图片记忆：

```text
/force_caption_forget
```

## 推荐设置

纯文本主模型建议保持：

- `记住本会话最近图片`：开启
- `最近图片记忆有效期`：300 秒
- `仅在疑似图片追问时复用最近图片`：开启
- `转述成功后移除原图`：开启
- `全部重试失败后移除原图`：开启
- `识图失败时静默处理`：开启
- `全部重试失败后不向用户反馈“没看到图片”`：开启
- `启用插件额外重试`：**关闭（AstrBot 4.28+ 推荐）**
- `识图失败最大重试次数`：0（只有开启上面的额外重试开关后才生效）
- `自然续聊优先复用上次图片转述`：开启
- `群聊图片触发时只聚焦当前轮`：开启
- `视觉请求串行保护`：开启
- `429/计费拒绝后的视觉调用冷却时间`：60 秒

> AstrBot 4.28+ Provider 已经自带底层请求重试，因此插件额外重试默认设为 0，避免“双层重试”放大 RPM。需要兼容旧 Provider 时仍可手动设为 1～2。
>
> 429/RPM/TPM、计费暂停和鉴权异常会立即熔断；多图也不会在这类错误后继续逐张追加请求。

## 状态命令

```text
/force_caption_status
```

状态页会显示：图片转述模型、失败重试次数、最近图片记忆开关、记忆有效期，以及当前会话是否已有缓存图片。

## v1.2.1 临时图片持久化

默认会把 `data/temp` 中的当前图片复制到插件数据目录，并改写当前消息的图片引用，以避免后续工具调用出现“图片文件不存在”。


## v1.2.2：自然续聊图片语境

除了“第二个是谁”“这张呢”这类明确追问外，现在也支持更自然的群聊用法：

```text
用户：[图片]
用户：这个超级好吃
用户：好想来买的
机器人：……（可直接结合刚才图片内容回复）
```

默认行为：

- 图片后的 90 秒内，发图本人继续聊天会沿用最近图片语境；
- 群聊中默认只对发图本人启用自然续聊，降低串图概率；
- 明确图片追问仍可在最近图片 TTL 内由其他人继续追问；
- 可在配置中关闭或调整 `natural_followup_*` 相关选项。


## v1.2.4：防重复识图与 RPM / TPM 熔断

v1.2.4 保留 v1.2.2 的自然续聊，但改变“自然续聊”的实现方式：

```text
用户：[图片]
        ↓ 视觉模型识别 1 次
用户：笑死
        ↓ 直接复用上一轮转述，不再识图
用户：确实
        ↓ 继续复用，不再识图
用户：右边那个人在干嘛？
        ↓ 需要新视觉细节，再识图 1 次
```

同时加入以下保护：

- 相同图片 + 相同问题短时缓存；
- 同一识图任务并发去重；
- 默认串行视觉请求，降低群聊瞬时请求峰值；
- 429 / RPM / TPM / 配额 / 计费暂停后自动冷却；
- 冷却期间有旧转述就优先复用，没有则静默降级；
- 多图只有在批量/格式类错误时才拆分，限流和服务端错误不会继续扩散请求；
- AstrBot 4.28+ 下插件额外重试默认关闭；即使旧配置遗留 `max_retries=2` 也不会自动生效，功能开关和次数配置仍保留。


## v1.2.5：群聊当前轮聚焦

针对多人群聊里“前几条文本没有触发回复，后面一张图片触发 LLM 后，模型顺手补回复前面旧消息”的情况，v1.2.5 新增默认开启的 `group_reply_scope_guard`。

它不会清空或裁掉群聊历史，而是把历史消息定位为**背景语境**：

```text
群友A：前一条普通聊天（未触发 LLM）
群友B：另一条普通聊天（未触发 LLM）
群友C：[图片]  ← 当前真正触发 LLM
              ↓
主模型仍看得到 A/B 的语境
但直接回复对象限定为 C 的当前消息 + 本轮图片
```

如果当前发言者明确说“刚才A说的那个呢？”或引用了前面的内容，模型仍可正常回应历史消息，因此不会牺牲群聊连贯性。这个保护只是本轮临时提示，**不会新增视觉模型调用，也不会增加 RPM**。
